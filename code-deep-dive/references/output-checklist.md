# 输出校验清单

阶段三执行本清单，逐项过，全部通过才交付。

## 1. 事实核对

- 每个模块抽查 3 处引用与原文比对；引用不足 3 处时全部核对。
- MCP 给的行号与原文不符时以原文为准，并在交付物的"校验记录"里记下这次偏差。
- 核对 `get_symbol_dependencies` 这类按简单名匹配的返回，剔除通用名造成的误报。
- 结论按三档分类：**已验证**（有 MCP 证据）、**推测**（有源码依据但无 MCP 边）、**未验证**（无依据）。后两档不得写成第一档。

## 2. 图校验

Mermaid 的写法要求见 `module-template.md` 的"Mermaid 写法要求"，这里只核对结果：

- 每个节点、每条实线都能对上源码或一次已确认的调用/数据传递。
- 虚线都在"易错点标注"表里有对应条目。
- 靠读源码推出的边，在图下方的依据说明里已写明是推测。
- 有渲染条件时渲染一遍确认语法通过；没有渲染条件时不把"渲染通过"当作完成标准。

## 3. 七项检查

交付前逐项勾选，缺项回到阶段二补齐，不用"略"或"同上"占位：

- [ ] 模块职责与原理剖析
- [ ] 逐段代码解析（每段带源码位置、原理说明、三维度建议表）
- [ ] 业务优化建议
- [ ] 示例代码与源码并排对比（"优化后"可运行，前置条件已写明）
- [ ] 不建议改的部分写明技术理由
- [ ] 业务代码数据流向图
- [ ] 易错点标注（可定位到字段、条件或异常分支）

## 4. 工具账本回填

在这一步回填，不要求分析过程中实时记账。按章节回查：这条结论是哪次 MCP 调用支撑的？支撑不上的降到"推测"档，或补一次调用。

账本表格式与工具参数见 `mcp-selection.md` 的"工具账本"节。

## 5. 索引与挂起项

- 生成总览文档：模块清单、文档目录、全局数据流向图、按 P0/P1/P2 排序的跨模块建议汇总。
- 索引里每条建议能跳到来源模块文档。
- 把所有"未验证"结论和缺证据的推断列成待办交给用户，写明每项缺什么证据、补哪一次调用能补齐。
- 阶段二因模块数超过 5 个而未做的模块，列进待办并标注优先级。
